# 29 · 部署与调度

> 章节：第六章 Harness 进阶

## 生产中会遇到的问题

在本机运行的 Agent 关掉终端就停止。使用者需要它持续可用，并且在指定时间自动执行任务。这涉及三个问题：程序以什么形式常驻、凭证如何管理、任务如何被触发。

## 底层机制

运行形态分四类：

| 形态 | 触发方式 | 适用场景 |
|------|----------|----------|
| 命令行工具 | 人工执行 | 开发与调试 |
| 常驻服务 | 消息驱动 | 群聊机器人、接口服务 |
| 事件驱动 | 外部事件 | 代码提交、审批完成之后执行 |
| 定时任务 | 时间 | 巡检、汇总、定期整理 |

调度系统需要处理的问题包括：时区、表达式解析、错过的任务如何处理、任务执行时间超过下一个触发点时如何处理、任务失败之后的处理方式。

## 实现要点

**进程管理。** 常驻服务需要自动重启与健康检查。拉起次数需要限制，否则配置错误会造成无限重启。

**全局单例。** 部分服务有身份约束，例如消息机器人只能有一个实例在监听。启动时需要通过锁文件或者分布式锁确保只有一个实例运行。

**凭证管理。** 凭证放在环境变量或独立的配置文件中，配置文件不进入版本管理。

**定时任务。** 表达式解析与时区处理应当使用成熟的库。任务定义保存在可热更新的配置文件中。

**任务队列。** 同时有多个任务需要执行时使用队列并限制并发数量。

**长任务与重启。** 任务状态需要持久化，重启之后能够判断哪些任务需要继续。

**日志轮转。** 记录文件按大小或时间切分，保留周期明确设置。

## pi 的做法

pi 提供了多种运行形态，它们共用同一套会话与循环机制。

**四种界面模式。**

| 模式 | 启动方式 | 特点 |
|------|----------|------|
| 交互模式 | `pi` | 终端界面，实时渲染会话与运行事件 |
| 打印模式 | `pi -p` | 执行一个提示词并输出最终结果，适合脚本调用 |
| JSON 模式 | 指定 JSON 输出 | 把运行事件按行输出为 JSON，适合管道处理 |
| RPC 模式 | `pi --mode rpc` | 常驻子进程，通过标准输入输出用 JSON 记录控制 |

`docs/how-pi-works.md` 明确说明：所有界面共用同一套 agent 与 session 机制。这意味着换一种接入方式不需要重写循环或状态管理。

**长时间运行由 RPC 模式承担。** RPC 模式是长驻子进程，客户端通过命令驱动它，事件持续流出。这一形态正是群聊机器人、编辑器插件这类常驻服务的载体。

**状态在文件里，重启即恢复。** 会话保存在 `~/.pi/agent/sessions/--<路径>--/<时间戳>_<会话标识>.jsonl`。路径部分由工作目录转换而来：去掉开头的分隔符，把斜杠与冒号替换成连字符。恢复方式是从文件读回会话树并选择活动分支。

**设置可以热更新。** 设置在 `~/.pi/agent/settings.json` 与项目 `.pi/settings.json` 两级，重试次数、重试基础等待、单次等待上限、缓存续期模式、HTTP 空闲超时等都在其中。修改之后不需要重新构建。

**定时与后台执行由编排层提供。** `pi-subagents` 的 `schedule.create` 支持按延迟或按 `every` 周期创建定时运行，选项包括时区、错过触发的补偿策略（`catchUp` 取 `none` 或 `latest`）、并发重叠策略。后台子智能体运行在独立的运行进程里，脱离发起会话之后继续执行，完成时主动通知。

**凭证与身份。** 凭证通过 `pi-ai` 的凭证存储管理，模型运行时会按供应方检查可用性并维护快照。这一层让「换凭证」与「换模型」都不需要改动循环代码。

**消息通道由扩展承担。** 本机的飞书扩展把群聊消息接入 pi：收到消息后启动一次运行，把事件流渲染成卡片，支持流式更新与按钮回调。这一层是形态上的「常驻服务」：进程长期运行，由外部消息驱动。

## 常见错误

第一个错误是使用 `nohup` 之类的方式启动。进程退出之后无人拉起，也没有健康检查。

第二个错误是多个实例同时监听同一条消息通道。消息被重复处理。

第三个错误是凭证写入配置文件并提交。凭证泄漏。

第四个错误是定时任务按本地时区解析，服务器使用另一个时区时执行时间与预期不符。

第五个错误是长任务没有状态记录。重启之后从头开始，前面完成的部分重复执行。

第六个错误是每种界面各写一套循环。行为不一致，修复需要改多处。

## 自检问题

1. 你的服务由什么程序管理，退出之后会被拉起吗？
2. 你换一种接入方式时，循环与会话管理需要重写吗？
3. 定时任务的时区与服务器时区一致吗？
4. 任务执行到一半进程重启，会怎么处理？
