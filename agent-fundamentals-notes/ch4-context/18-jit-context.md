# 18 · Just-In-Time Context

> 章节：第四章 Context Engineering

## 生产中会遇到的问题

为了让模型「知道得更多」，程序在任务开始前把整个项目的背景文档、全部接口说明、相关历史记录一次性放入请求。结果是请求长度迅速接近上限，模型对其中大部分内容没有使用，真正相关的部分被大量无关内容稀释。

## 底层机制

提前装配的前提是程序能够准确判断本次任务需要哪些内容。这个判断在任务开始时往往做不出来，因为任务的具体走向取决于模型前几步的发现。按需获取把判断推迟到信息充分的时候。

按需获取要求两个条件同时满足：

- 模型知道有什么内容可以读取，否则它不会去读；
- 模型有稳定的读取手段。

只满足第二个条件时，模型不知道有哪些文件或资料存在，不会主动尝试。只满足第一个条件时，模型知道内容存在但无法读取。

## 实现要点

**提供索引。** 项目背景用一个目录说明文件承载，包含各目录的用途与关键文件路径。

**在系统提示词里写明读取方式。** 「需要项目约定时读取某个目录下的文件」这类说明让模型知道索引与内容的对应关系。

**用结构化的返回格式。** 目录列表返回文件名与用途，文件读取返回带行号的内容与总行数。格式固定之后模型的行为也更稳定。

**混合策略。** 少量强制性约束提前放入，事实性内容按需读取。判断依据是这条内容是否在所有任务中都必须生效。

**提供全局视野。** 只给索引时模型容易反复探索同一区域，因为它不知道哪些部分已经看过。

## pi 的做法

pi 的按需获取有三条可核对的实现路径。

**路径一：Skill 的两阶段加载。** 常驻提示词里只有名称、说明与路径。`formatSkillsForPrompt` 生成的清单末尾会附带一句读取方式说明：

```
Use the read tool to load a skill's file when the task matches its description.
When a skill file references a relative path, resolve it against the skill directory
(parent of SKILL.md / dirname of the path) and use that absolute path in tool commands.
```

第二句是必要补充：只给出位置还不够，模型还需要知道相对路径按哪里解析。缺少这句话时，Skill 里引用的脚本路径会按工作目录解析而找不到。

清单里同时含一句明确的自助说明，指出模型可能漏加载某个相关 Skill，使用者可以用 `/skill:name` 强制加载。也就是说，按需获取的漏加载问题是已知的，pi 用一条显式的强制入口来兜底。

**路径二：文档索引段。** 系统提示词的 `docs` 段落只给出文档路径，并在同一段里写明解析规则：「读取 pi 文档时，`docs/...` 相对于文档目录解析，`examples/...` 相对于示例目录解析，不要按当前工作目录解析」。随后还列出「问到扩展、主题、技能、提示词模板、快捷键、SDK、自定义供应方等问题时对应读哪个文件」。这一段是索引与路由规则的组合，内容本身不在其中。

段落开头还写了一句约束：只在被问到 pi 自身时才读取这些文档。

**路径三：项目上下文文件的边界。** 上下文文件（`AGENTS.md`、`CLAUDE.md` 等）在启动时被完整读入，属于提前装配的部分。pi 对这部分成本的处理方式是限制范围与形式：只读取被发现的那几个文件，渲染进独立的 `project_context` 段落，每个文件带路径标签。因此使用者可以按需决定这些文件里放多少内容，而 pi 提供的是「放在哪里、以什么形式放在请求里」的机制。

**代价的可见位置。** 按需获取会增加循环轮数。pi 在读取工具上直接做了应对：`read` 的参数里有 `offset` 与 `limit`，描述里写明「需要完整文件时用 offset 继续读取」。这一次性的引导把多次零散读取合并成有序的连续读取，减少了探索轮数。

## 常见错误

第一个错误是提供内容但不提供索引。模型不知道内容存在，或者只能靠猜测路径。

第二个错误是索引过于详细。索引本身变成了完整文档，占用与提前装配相同。

第三个错误是给出位置但不说明相对路径的解析基准。Skill 与文档里引用的文件找不到。

第四个错误是假设模型总会加载需要的 Skill。缺少强制加载入口时，漏加载无法补救。

第五个错误是忽略读取成本。每一轮读取都会把结果加入历史，长任务中按需获取的累计开销可能超过提前装配。

## 自检问题

1. 你的系统提示词里，哪些内容在所有任务中都必须生效？
2. 模型知道有哪些资料可以读取吗，通过什么方式知道？
3. 你在索引里说明了相对路径的解析基准吗？
4. 模型漏加载某个资料时，有没有强制加载的入口？
