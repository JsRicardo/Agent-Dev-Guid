# 10 · Deferred Loading 与动态工具集

> 章节：第三章 Tool System

## 生产中会遇到的问题

接入的工具逐步增多之后会出现两个现象：模型选择错误的比例上升，其中多数错误发生在功能相近的两个工具之间；每一轮请求的 Token 开销上升，因为完整工具定义需要随每次请求发送。

## 底层机制

工具的选择过程是在同一份候选列表上做判断。候选数量增加会带来两个变化：相近工具之间的区分难度上升，模型在判断时使用的注意力被分散。经验阈值在二十个左右，超过之后选择错误开始明显增加，具体数值取决于工具之间的相似程度。

工具定义本身也占用请求长度。一个参数复杂的工具定义可能消耗数百 Token，三十个工具意味着每一轮请求都有上万 Token 的固定开销。

## 实现要点

**按任务阶段分组。** 把工具集合按使用场景分成若干组，同一时刻只暴露当前阶段需要的组。

**元工具搜索。** 保留少量常用工具，其余工具通过搜索方式按需加载。

**描述精简。** 完整描述只在工具被加载之后提供，列表阶段只提供名称与简短说明。

**角色绑定工具集。** 不同的子智能体暴露不同的工具集合。负责检索的子智能体不需要写入工具，负责修改的子智能体不需要搜索网页的工具。

## pi 的做法

pi 的动态工具集有一个少见的设计：工具集合的变化以消息的形式写进会话记录。

**变化如何被声明。** `pi-agent-core/dist/agent-loop.js` 里的 `declareToolChanges` 在每一轮请求之前比较两件事：会话记录里已声明的工具，与 `context.tools` 里当前可以执行的工具。差集写入一条 `role: "system"` 消息的 `toolsAdded` 与 `toolsRemoved` 字段。

```typescript
const changes = getToolStateChanges(
  getCurrentTools([...context.messages, ...baseline]),
  (context.tools ?? []).map(toToolDeclaration),
);
```

这样做的结果是：回放会话记录就能得到当前提示词与工具集合，不需要额外的状态文件。`docs/session-format.md` 里对此有明确说明。

**系统提示词同样按段落打补丁。** `dist/core/system-prompt.js` 的 `diffSystemPromptSections` 比较当前段落与期望段落，只把变化的段落写进系统消息的 `sections` 字段，`null` 表示删除该段落。技能被加载之后只有 `skills` 段落变化，`preamble`、`tools`、`docs` 等段落保持不变，提示词缓存因此不受影响。

**工具集合内置了两种预设。** `dist/core/tools/index.js` 导出了几组现成的集合：

| 函数 | 内容 | 用途 |
|------|------|------|
| `createCodingTools` | `read`、`bash`、`edit`、`write` | 完整能力 |
| `createReadOnlyTools` | `read`、`grep`、`find`、`ls` | 只读任务 |
| `createAllTools` | 全部 8 个 | 需要完整集合时 |

只读集合与完整集合的区分在代码里是显式的函数，调用处按场景选择，不依赖运行时过滤。

**子智能体侧用白名单收窄。** `pi-subagents` 的 agent 定义用 frontmatter 声明工具集合。

```yaml
---
name: scout
description: Fast codebase recon
tools: read, grep, find, ls
---
```

`tools` 字段是严格白名单：没有列出的内置工具子智能体拿不到。`mcp:` 前缀的条目单独解析，只授予指定的 MCP 工具，不会连带放开内置工具。

## 常见错误

第一个错误是把所有工具一次性暴露。接入成本低，运行时成本高。

第二个错误是分组依据按实现模块划分。模型判断依据是任务意图，按代码目录分组会让模型找不到需要的工具。

第三个错误是把工具集合的变化只放在内存里。会话恢复之后工具状态与提示词不一致，回放无法复现当时的行为。

第四个错误是加载之后不释放。工具集合只增不减，长时间会话之后又回到了全部暴露的状态。

第五个错误是只按工具名称做白名单。同一个工具的不同参数风险差别很大，白名单需要与参数校验配合。

## 自检问题

1. 你的工具总数是多少，模型选错时通常发生在哪两个工具之间？
2. 工具集合的变化会被记录下来吗，会话恢复之后能复现吗？
3. 系统提示词是整段重写还是按段落打补丁？
4. 你的子智能体拿到的是完整工具集还是白名单？
